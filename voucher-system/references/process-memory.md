# Process Memory And Continuous Improvement

This skill should improve over time, but only with the user's approval.

## Core rule

When a new process, accounting rule, naming rule, or extraction technique is discovered during a run, ask:

`Should I record this as the new standard process for Voucher System?`

Do not treat the new behavior as permanent unless the user says yes.

## What can be recorded

- new source-document types
- new account-mapping rules
- new particulars wording patterns
- new naming conventions
- new validation or review steps
- new exceptions that recur often enough to justify a standing rule

## What should not be auto-recorded

- one-off corrections
- uncertain accounting choices
- user guesses
- exceptional vendor-specific workarounds unless the user explicitly promotes them to a standard

## Recording behavior

When the user approves recording a change:

1. summarize the rule in one sentence
2. confirm where it belongs:
   - workflow rule
   - naming rule
   - accounting rule
   - source-routing rule
   - particulars rule
3. update the skill reference files
4. mention that future runs can reuse the rule

## Review behavior

If a new rule conflicts with an older rule:

- show the conflict briefly
- ask which rule should remain the standard
- do not overwrite the older rule without confirmation

## Session memory vs. skill memory

- Session memory is temporary and can guide the current run.
- Skill memory is durable and should be updated only after explicit approval.

## Recommended maintenance habit

After any materially new voucher workflow is completed, ask once whether the process should be recorded. Do not ask repeatedly within the same run if the user already declined.
